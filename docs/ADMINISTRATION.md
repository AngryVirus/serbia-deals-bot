# Управление пользователями

В @SerbiaDealsBot кнопка «Админка» появляется только у команды. Роли и блокировки хранятся отдельно от пользовательских настроек и не переносятся из Jobs-бота автоматически.

| Роль | Возможности |
|---|---|
| Модератор | Блокировать обычных пользователей с указанием причины |
| Администратор | Блокировать и разблокировать пользователей, назначать и снимать модераторов |
| Владелец, ID 340780041 | Всё перечисленное, назначать/снимать администраторов, статистика, журнал, состояние магазинов |

Изменять собственные права, блокировать себя, владельца или участников равного/более высокого уровня нельзя. Администратор не может разблокировать администратора, даже если тот временно заблокирован владельцем.

«Команда» → человек → назначить, повысить, понизить, снять полномочия. Каждое изменение требует отдельного подтверждения и отправляет адресату уведомление с фактическим исполнителем. Чтобы найти нового участника по @username, он должен ранее открыть бота. Перед подтверждением имя повторно сверяется через Telegram по числовому ID. При недоступной проверке используйте ID; произвольные приватные @username Telegram не разрешает надёжно находить через Bot API.

Блокировка: ID или @username → причина (до 300 символов) → предпросмотр → подтверждение. Уведомление пользователю — картинка с причиной и исполнителем, кнопкой связи с @AngryVirus. В интерфейсе подтверждения кнопки связи нет. После этого бот не отвечает заблокированному пользователю и не отправляет уведомления о ценах. Разблокировка также отправляет картинку; подписки не включаются принудительно. ID ещё не открывавшего бота можно заблокировать заранее; уведомление будет доставлено при первом обращении, без создания профиля.

Управляющие сообщения удаляются после принятия. `/cancel` отменяет ввод. Переход в другой раздел отменяет старое подтверждение.

Статистика владельца: общее количество, активность и новые профили за сегодня/7/30 дней по времени Сербии, доступные подписки, недоступные адресаты, подтверждённые Telegram блокировки бота, баны и численность команды. История регистрации старых профилей неизвестна и не подменяется сегодняшней датой. Обновление перечитывает счётчики и не запускает сбор. Журнал действий команды виден только владельцу; записи старше 10 дней удаляются при работе бота и независимой служебной проверке.

## Надёжность доставки и права

Проверки прав работают на сервере, включая поддельные и старые callback-запросы. Входящие обновления, решения команды и отправители уведомлений используют общую SQLite аренду пользователя. Запись решения и аудита атомарна и требует действующих аренд исполнителя и адресата; версия предотвращает повторное подтверждение. Бан не удаляется через `/delete`.

Уведомление получает стойкую отметку `sending` **до** отправки. После таймаута или сбоя между отправкой и записью результата оно не повторяется автоматически: Telegram не предоставляет ключ идемпотентности, поэтому одновременно гарантировать доставку и исключить повтор невозможно. Интерфейс сообщает о неопределённой доставке. Явный ответ 429 допускает повтор после указанной задержки; 403 — только после нового подтверждённого обращения пользователя.

`Deliver access notices` проверяет ожидающие уведомления каждые 15 минут отдельно от сбора цен и рассылок о снижении цены. GitHub может задерживать расписание. В обычном случае отправка происходит сразу после подтверждения. Для неизвестных ID проверка не создаёт профили и не отправляет сообщения до первого обращения.

`collector.operations diagnose` проверяет рендеринг картинок блокировки/разблокировки в Cloud на вымышленных данных, без изменения ролей и отправки сообщений. Тесты SQLite используют исключительно локальные тестовые профили. Секреты и личные данные в вывод диагностики не включаются.
