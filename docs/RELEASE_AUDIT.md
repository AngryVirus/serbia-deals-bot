# Аудит перед публичным запуском — 21.10.2026

Проверены актуальные обработчики Telegram, SQLite, поиск и уточнения, корзина,
переводы, роли и баны, рекламная и ценовая доставка, импорт CSV и workflows.

Опубликована ревизия **28**, код `16126b6` (PR #51). Последующая проверка:

## Исправления

| Участок | Ошибка и исправленное поведение |
|---|---|
| Ценовые уведомления | Отключённые/удалённые пользователи и снятые отслеживания больше не занимают первые пять событий и не блокируют доставку остальным. |
| Дубли уведомлений | Несколько ожидающих падений цены объединяются в одно актуальное сообщение; срок 429 сохраняется. Sending/uncertain не переигрываются. |
| Конкурентная подготовка | Baseline и событие проверяют прежнее значение и действующее предложение. Старый snapshot не откатывает новый baseline; отправка фиксирует baseline до API, включая сбой на границе суток. |
| Выбор в корзине | Любая выбранная карточка проверяется против запроса позиции, даже без фильтров. Старая карточка молока не заполняет курицу. |
| Замена SKU | Запятые и `× 2` в исходном названии после замены остаются одной позицией; стоимость и количество не удваиваются. Legacy combined-списки поддерживаются. |
| Удаление данных | Подтверждение привязано к пользователю, nonce, сроку 10 минут и snapshot удаляемых данных. Отмена, новая корзина, повтор и старый профиль не удаляются старой кнопкой. |
| Уточнения | Пустой бренд не скрывает остальные; открытие другого бренда/вида игнорирует зависимую упаковку, не сбрасывая активные фильтры до применения. |
| Отслеживания | Лимит 100 больше не даёт ложного успеха, гонка не превышает его. Исчезнувшее предложение не вызывает ошибку; доступны последние пять записей. |
| Команды | /help и /delete прерывают ввод причины бана, а не становятся её текстом. |
| Свежесть импорта | Вчерашний резервный CSV не заменяет сегодняшний прайс: проверки до lease, после него и в финальном CAS. Исправленный прайс того же дня принимается. |
| Штрихкоды | GS1 GTIN-8 и нулевые дополнения получают одинаковую внешнюю идентичность; внутренние restricted circulation коды не объединяются между сетями. |
| Совместимость выбора | Старый local-ID восстанавливается через стабильный offer ID к текущему GTIN без переписывания корзины и подписок. Повторное отслеживание не создаёт дубль. |
| Будущие акции | Корректная будущая скидка сохраняется и включается по дате без обязательного изменения исходного CSV. |
| Планировщик | Долгий сбор не вытесняет pending watchdog/доставки. Ручной и плановый импорт разделяют свою группу, остальные задачи — отдельные. Worker leases рекламы и health различаются. |
| Публикация | diagnose завершается ошибкой при провале обязательной группы. Stage сверяет полный установленный код и ревизию; последующая diagnose с require_deployed требует точного совпадения. |

Правила идентичности сверены с GS1 General Specifications 26.0:
https://ref.gs1.org/standards/genspecs/
В публичном срезе 129 552 предложений исправляется 986 local-ID, 365 внешних
кодов, 149 межсетевых совпадений; стабильные offer IDs сохраняются. Parser salt
изменён на prices-v3, поэтому обычный следующий импорт применит новые правила
даже при неизменном файле издателя. Это проверка публичного среза, не заявление
о переимпорте действующей базы. Цены вручную не исправлялись.

## Внешняя настройка GitHub

На момент аудита GET branches/main возвращает protected=false, активных ruleset
для main нет. PUT настройки защиты через существующее подключение возвращает
HTTP 403 Resource not accessible by integration. Личный токен не запрашивался.

Готовая конфигурация: [.github/branch-protection.json](../.github/branch-protection.json).
Владелец репозитория может применить её в GitHub:

1. Settings → Branches → Add classic branch protection rule, шаблон `main`.
2. Require a pull request before merging. Обязательных одобрений — 0, чтобы
   владелец мог сам сливать PR после проверок.
3. Require status checks: `tests`, `security`; Require branches to be up to date.
4. Do not allow bypassing the above settings / применить к администраторам.
   Force pushes и удаление ветки не разрешать.

Процесс PR и обе проверки уже совместимы с этой конфигурацией. В данном аудите
публикация также проводится только после успешных checks текущего head PR.

## Сохранённые ограничения

- Наличие/цена конкретного филиала не подтверждаются сетевым прайсом. GitHub
  schedule и внешние CSV не гарантируют точного времени обновления.
- Неоднозначная отправка не повторяется автоматически: возможен пропуск,
  одновременно гарантировать отсутствие дубля и доставку Telegram не позволяет.
- После дополнительного согласования внедрены ежедневный зашифрованный backup
  и локальное восстановление с проверкой. Первая реальная копия сохранена,
  восстановление проверено без отправок. Порядок и границы восстановления:
  [BACKUP_AND_RECOVERY.md](BACKUP_AND_RECOVERY.md); фактические запуски — в
  [RELEASE_STATUS.md](RELEASE_STATUS.md). Наличие отдельного платформенного
  восстановления Telegram по-прежнему не подтверждено.
- Технические квитанции рекламы пока сохраняются до удаления профиля; общий
  срок для старых кампаний потребует отдельного lifecycle с tombstones.

Новых пунктов пользовательского меню нет. Корзины, роли, секреты и архитектура
сохранены; доступ к владельцу по числовому ID проверяется на сервере.
