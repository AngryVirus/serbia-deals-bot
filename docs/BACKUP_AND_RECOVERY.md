# Резервные копии и восстановление

Workflow **Deals encrypted user-data backup** запускается ежедневно в 04:23 UTC
(06:23 по летнему времени Белграда, 05:23 по зимнему) и вручную через Actions.
GitHub может задерживать плановые запуски. Платных сервисов и новых секретов нет.

## Что сохраняется

- Профили и предпочтения уведомлений зарегистрированных пользователей.
- Корзины, количества, выбранные товары и уточнения.
- Подписки на цены и их исходные значения.
- Роли и баны, включая решения по пользователям без профиля.
- Начало учёта пользователей и лимит рекламных запусков.

Каталог цен можно собрать заново; он не входит в эту копию. Не сохраняются
очереди доставки, рекламные кампании, журнал действий, блокировки workers,
кэш картинок и перевода. Исходный пользовательский payload сохраняется внутри
зашифрованного архива, но временные поля удаляются при восстановлении.

Снимок создаётся одним SQL-запросом для всех таблиц. В этом же запросе
проверяется отсутствие активных пользовательских leases: если идёт изменение
корзины/профиля/прав, операция ждёт следующую свободную границу. Затем страницы
читаются из неизменяемой технической копии. После выгрузки она удаляется;
оставшаяся после сбоя копия удаляется следующим созданием через 24 часа.
Обычное меню и отправка сообщений не вызываются.

## Шифрование и хранение

Файл `users.sdcbk` шифруется AES-256-GCM. Для каждого файла создаются случайные
salt и nonce; ключ выводится через HKDF-SHA256 из существующего
`SERBIA_DEALS_CLOUD_TOKEN`. У Deals свой формат и контекст шифрования.
Заголовок и содержимое проверяются до выдачи расшифрованных данных.

В Actions загружаются **только шифротекст и обезличенный отчёт** с количеством
строк и контрольными суммами. Артефакт `encrypted-users-<run_id>` хранится
**7 дней**. Репозиторий публичный: доступ читателей к артефакту не должен
считаться защитой; данные защищает именно шифрование. Не загружайте локальную
восстановленную SQLite в GitHub, чат или публичное хранилище.

Смена Cloud token изменит ключ новых копий. **Для старой копии нужен тот token,
с которым её создали.** В этой задаче token не меняется и не ротируется.
При будущей ротации сначала отдельно решите, где безопасно сохранить прежний
ключ на оставшийся срок хранения. Не присылайте его в чат.

Удаление профиля в боте действует на рабочую базу. Более ранняя зашифрованная
копия может содержать этот профиль до истечения 7 дней. Перед аварийным возвратом
старой копии нужно повторно применить удаления и изменения доступа, произошедшие
после времени снимка. Автоматической замены рабочей базы из архива нет.

## Что проверяет каждый backup

1. Полный набор таблиц, столбцов и количество полученных строк.
2. SQLite integrity_check и digest всех исходных записей, а не только счётчиков.
3. Аутентифицированное расшифрование фактически записанного файла.
4. Запуск кода приложения на временной локальной SQLite без служебных ключей.
5. Сохранение корзин, подписок и прав; отсутствие живых очередей и отправок.
6. Повторную проверку соответствия файла отчёту непосредственно перед upload.

Сбой любого шага завершает workflow ошибкой; непроверенный архив не загружается.
В логах нет записей пользователей, корзин, причин банов и значений секретов.

## Проверка и локальное восстановление

Скачайте оба файла из одного успешного запуска Actions в закрытую локальную
папку. Нужны Node 24 и Python 3.12; для локальной проверки сеть не используется.
Задайте `TGCLOUD_TOKEN` через защищённое окружение, без значения в истории команд
и без отправки в чат. Используйте версию кода, указанную в выбранном запуске.

```sh
python3 serverless/backup.py verify-pair /private/backup/users.sdcbk
python3 serverless/backup.py restore-local /private/backup/users.sdcbk \
  --output /private/recovery/restored.sqlite
```

Существующий output не перезаписывается; новый файл имеет права 0600.
Восстановленная копия остаётся **на паузе**. Временные UI-состояния и старые
подтверждения удалены; рекламных кампаний и очередей доставки нет; уведомления
о прежних банах/ролях подавлены. Значения отслеживаемых цен сбрасываются только
в восстановленной копии: первая подготовка после нового сбора устанавливает
актуальную базовую цену без рассылки исторического падения.

Это локальное восстановление и проверка, **не публикация базы в Telegram**.
Для реальной аварии сначала сохраните уцелевшую рабочую базу, проверьте права
и удаления после снимка, соберите свежий каталог и подготовьте совместимый
импорт в доступном тогда интерфейсе Telegram Serverless. Только после этого
отдельно активируйте бот. Восстанавливать рабочую базу ради теста нельзя.

## Защита main

Процесс PR уже запускает обязательные `tests` и `security`. Готовая конфигурация:
[branch-protection.json](../.github/branch-protection.json).
Существующее подключение GitHub возвращает 403 при настройке защиты; ему
недоступна Administration. Личный token для этого не нужен.

Владелец может включить правило в
[Settings → Branches](https://github.com/AngryVirus/serbia-deals-bot/settings/branches):

1. Add classic branch protection rule, Branch name pattern `main`.
2. Require a pull request before merging — включить; Require approvals — выключить.
3. Require status checks: `tests`, `security`; Require branches to be up to date — включить.
4. Do not allow bypassing the above settings — включить.
5. Force pushes и удаление ветки — оставить запрещёнными.
